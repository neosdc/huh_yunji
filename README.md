# 구구단 놀이터

초등학생이 구구단, 덧셈·뺄셈, 여러 자리 수 곱셈, 영어 파닉스를 놀이처럼 익힐 수 있는 웹 게임입니다.
빌드 도구 없이 정적 파일(`index.html` + `phonics.js`, `phonics.css`, `voice.js`)만으로 동작하며, **Google 로그인한 부모 계정**으로만 쓸 수 있습니다. 아이별 프로필을 만들어 학습 진행과 풀이 기록을 [Supabase](https://supabase.com)에 저장합니다.

## 실행 방법

먼저 아래 "로그인과 데이터 저장"의 설정(Supabase 프로젝트, Google 로그인, `GUGUDAN_CONFIG`)을 해야 게임이 열립니다. 설정이 비어 있으면 "서비스 연결 설정이 아직 없어요" 화면만 나옵니다.

- **로컬 서버:** 저장소 폴더에서 `python3 -m http.server 8000`을 실행하고 `http://localhost:8000`에 접속합니다. 이 주소를 Supabase의 Redirect URL에 등록해야 로그인이 됩니다. 로그인 때 주소가 필요해서 `index.html`을 파일로 바로 열면(`file://`) 로그인할 수 없습니다.
- **호스팅:** 저장소 파일(`index.html`, `phonics.js`, `phonics.css`, `dashboard.js`, `dashboard.css`, `voice.js`, `manifest.json`, `phonics/`, `favicon.ico`)을 GitHub Pages, Nginx, S3 같은 정적 호스팅에 올리면 됩니다. 직접 운영하는 서버 코드는 없고, 로그인과 저장은 Supabase가 맡습니다. `favicon.ico`가 없어도 게임은 동작하고 탭 아이콘만 기본 모양으로 나옵니다.

제목 폰트(Jua, Gowun Dodum)는 Google Fonts에서 불러옵니다. 오프라인이거나 폰트를 불러오지 못하면 시스템 기본 폰트로 표시되며 동작에는 영향이 없습니다.

## 메뉴 구성

홈 화면 상단 탭(구구단 / 덧셈·뺄셈 / 곱셈 / 파닉스)으로 네 놀이터를 전환합니다. 선택한 탭은 다음 접속 때도 유지됩니다.

### 활동 기록 대시보드

홈 화면의 **📊 기록** 버튼(프로필 고르는 화면의 "활동 기록 보기"도 같습니다)으로 엽니다. 놀이터와 같은 페이지 안의 화면이라 따로 배포할 것이 없고, GitHub Pages 같은 정적 호스팅에서 그대로 서비스됩니다. 로그인한 부모 계정의 프로필만 볼 수 있고, 다른 계정의 데이터는 DB(RLS)가 막습니다.

- **프로필 조회:** 위쪽 이름 버튼으로 프로필을 바꿔 가며 봅니다. 지금 놀고 있는 프로필을 바꾸는 것이 아니라 기록만 보는 화면입니다.
- **푼 문제 수:** 화면을 열어 둔 시간이 아니라 **풀이가 기록된 만큼** 셉니다. 구구단·덧셈·뺄셈·곱셈은 연습하기와 도전하기의 풀이(`attempts`), 파닉스는 게임에서 답한 소리·단어 하나하나(`ph_attempts`)가 기준입니다. 배우기 화면은 기록되지 않아 세지 않습니다. 틀려서 다시 나온 문제도 한 번 더 푼 것으로 세고, "처음에 맞힌 비율"은 처음 나온 문제만으로 계산합니다.
- **일간 / 주간 / 월간:** 최근 14일, 8주(월요일 시작), 6개월을 놀이터별로 색을 나눈 막대로 보여 줍니다. 막대를 누르면 그 기간의 놀이터별 푼 문제, 맞힌 문제, 연습·도전 횟수가 나옵니다. 날짜는 보는 기기의 시간대 기준입니다. 위쪽에는 오늘·이번 주·이번 달·전체 합계가 있습니다.
- **진도율:** 구구단은 익힌 칸(72칸 중)과 단별 현황, 덧셈·뺄셈은 1-6단계, 곱셈은 1-5단계의 최고 별, 파닉스는 단계 클리어와 숙달한 소리·단어를 보여 줍니다. `profile_state`의 진행 상황을 읽습니다.
- 풀이 기록은 이 기능이 들어간 뒤부터 쌓입니다. 그 전에 푼 문제는 진도율에는 반영되지만 푼 문제 수에는 들어 있지 않습니다.

### 구구단 놀이터

| 모드 | 설명 |
| --- | --- |
| 배우기 | 단을 골라 곱셈식이 어떻게 만들어지는지 그림과 함께 봅니다. |
| 연습하기 | 4지선다로 풀며, 틀린 문제는 설명과 함께 다시 출제됩니다. |
| 도전하기 | 키패드로 정답을 직접 입력합니다. |

- 모든 문제에는 **10초 제한 시간**이 있습니다. 시간이 지나면 오답으로 처리되고 풀이를 보여 준 뒤 다시 출제됩니다.
- 사실(예: 7×8)마다 숙련도를 기록하고, 약한 문제를 더 자주 출제합니다.

### 천만냥냥 (구구단 놀이터 캐릭터)

'천만냥'이라는 큰돈을 들고 다니며 재물 복을 부르는 고양이 '냥'입니다. **구구단 놀이터와 파닉스 놀이터**에 나옵니다. 파닉스에서는 홈, 단계 화면, 결과 화면, 문제 푸는 중(정답·오답 반응)에 말풍선 글자로만 말합니다(음성 파일 없음). 덧셈·뺄셈과 곱셈 놀이터에는 나오지 않습니다.

- **홈 화면:** 환영 인사를 말풍선으로 합니다. 인사는 여러 개 중 무작위로 고릅니다.
- **배우기:** 식을 한글로 읽은 문장(예: "칠 삼은 이십일")을 천만냥냥이 말풍선으로 말합니다. 앞으로/뒤로 넘길 때마다 새 문장을 말합니다.
- **문제를 풀 때(연습하기·도전하기):** 캐릭터는 화면에서 크게(약 116px) 보입니다. 정답이면 "잘했냥 / 좋냥 / 멋지냥 / 훌륭하냥 / 대단하냥 / 맞냥" 중 하나, 오답이거나 시간이 끝나면 "아쉽냥 / 아니냥 / 틀렸냥 / 노력해냥 / 분발해냥" 중 하나를 무작위로 말합니다.
- **제한 시간이 절반 이하로 남으면:** "시간이 없냥 / 자냥 / 졸고있냥 / 모르냥 / 느긋하냥 / 뭐하냥" 중 하나를 무작위로 말합니다. 문제마다 한 번만 말합니다.
- **결과 화면:** 점수(처음에 맞힌 문제 수 / 전체 문제 수)에 따라 말이 달라집니다.

| 점수 | 대사 | 모습 |
| --- | --- | --- |
| 만점 | 훌륭하냥! | 천천히 둥둥 떠다님 |
| 85% 이상 (만점 제외) | 조금만 더 노력하냥 | 가만히 있음 |
| 60% 이상 85% 미만 | 노력하냥 | 가만히 있음 |
| 60% 미만 | 더 많은 노력이 필요하냥 | 가만히 있음 |

- **음성:** 말풍선 대사는 소리로도 나옵니다(소리를 켠 경우). 인사는 처음 한 번만 소리로 말하고(새로고침해서 바로 들어오면 시작 화면을 한 번 누른 뒤에 나옵니다), 이름이 들어가는 인사("영희야! 어서 와냥! …")는 이름을 미리 녹음할 수 없어서 말풍선에는 이름이 붙고, 음성은 이름을 뺀 문장("어서 와냥! …")만 나옵니다. 음성 파일은 승인된 계정만 내려받을 수 있고, 받지 못하면 소리 없이 말풍선만 나옵니다. 자세한 내용은 아래 "천만냥냥 음성"을 참고하세요.
- 이미지는 `index.html`의 CSS 변수(`--nyang`)에 WebP data URI로 들어 있어 별도 이미지 파일이 필요 없습니다. 시스템에서 '동작 줄이기'를 켜 두면 둥둥 떠다니는 움직임과 말풍선 애니메이션이 꺼집니다.

### 덧셈·뺄셈 놀이터

연산(덧셈 / 뺄셈 / 섞어서)과 단계(1-6단계 또는 전체)를 고릅니다.

| 단계 | 내용 |
| --- | --- |
| 1 | 합이 10 이하인 덧셈, 10 이내의 뺄셈 |
| 2 | 받아올림이 있는 덧셈, 받아내림이 있는 뺄셈 (20 이내) |
| 3 | 두 자리 수 ± 한 자리 수 |
| 4 | 두 자리 수 ± 두 자리 수 |
| 5 | 세 자리 수 ± 두 자리 수 |
| 6 | 세 자리 수 ± 세 자리 수 |

- 결과는 항상 1 이상이고, 합은 1000을 넘지 않습니다.
- **배우기:** 1-2단계는 십 프레임(점 그림)으로 "10 만들기"를 보여 주고, 3-6단계는 세로셈에 받아올림·받아내림 표시를 붙여 단계별로 설명합니다. 십의 자리가 0인 연속 받아내림도 설명합니다. 식의 한글 읽기와 단계별 팁도 함께 나옵니다.
- **연습하기·도전하기(세로셈 입력):** 문제를 세로셈으로 보여 주고 자릿수마다 칸을 눌러 입력합니다. 암산이 어려운 큰 자릿수도 한 자리씩 풀 수 있습니다. 연습하기와 도전하기는 입력 방식이 같습니다.
  - 아래쪽 큰 칸이 **답의 각 자릿수**입니다. 일의 자리 칸이 먼저 선택되어 있고, 숫자를 누르면 왼쪽 칸(십, 백 …)으로 자동으로 넘어갑니다. 다른 칸은 눌러서 고를 수 있습니다.
  - 위쪽 작은 버튼은 **받아올림·받아내림 표시**입니다. 덧셈에서는 받아올림이 일어나는 자리의 버튼을 누르면 `+1`, 뺄셈에서는 십의 자리 등 빌려주는 자리의 버튼을 누르면 `−1`이 켜지고, 다시 누르면 꺼집니다. 일의 자리에는 버튼이 없습니다(올림을 받거나 빌려줄 수 없기 때문). 이 표시는 풀이를 돕는 용도이고 채점에는 쓰이지 않습니다.
  - `지움`은 선택한 칸의 숫자를 지우고, 이미 빈 칸이면 오른쪽 칸으로 돌아가 지웁니다. 키보드에서는 숫자 키, Backspace, Enter(확인), 방향키(←/→로 답 칸 이동, ↑/↓로 선택한 자리의 올림·내림 표시 켜고 끄기)를 쓸 수 있습니다.
  - 답 칸은 가장 높은 자리부터 이어서 채워야 합니다. 중간에 빈 칸이 있으면 채점하지 않고 알려 줍니다. 맨 앞 칸을 비워 두거나 0을 써도 같은 수로 봅니다.
  - 덧셈은 두 수 중 긴 쪽보다 한 자리 많은 답 칸(받아올림으로 자리가 늘 때를 위해), 뺄셈은 긴 쪽과 같은 수의 답 칸이 나옵니다.
  - 틀리면 세로셈 풀이(받아올림·받아내림 표시)와 단계별 설명을 보여 준 뒤 다시 출제합니다. 이전의 보기 4개 방식은 덧셈·뺄셈에서 쓰지 않습니다.
- **범위를 정해서 도전하기:** 1-6단계 중 원하는 단계를 여러 개 골라 그 범위에서만 출제합니다. 하나도 고르지 않으면 시작할 수 없습니다.
- **제한 시간(단계별):** 1-3단계 10초, 4단계 15초, 5단계 20초, 6단계 25초. 막대 게이지는 문제마다 자기 제한 시간에 맞춰 줄어듭니다.

### 곱셈 놀이터

구구단(한 자리 × 한 자리)을 넘어서 여러 자리 수 곱셈을 익힙니다. 한 자리 × 한 자리는 구구단 놀이터에서 다루므로 이곳에서는 출제하지 않고, 가장 어려운 단계는 세 자리 × 두 자리입니다. 단계를 고르거나 "모든 단계 섞기"를 고릅니다.

| 단계 | 내용 |
| --- | --- |
| 1 | 두 자리 × 한 자리, 올림 없음 (예: 21 × 4) |
| 2 | 두 자리 × 한 자리, 올림 있음 (예: 47 × 6) |
| 3 | 세 자리 × 한 자리 (예: 328 × 7) |
| 4 | 두 자리 × 두 자리 (예: 36 × 47) |
| 5 | 세 자리 × 두 자리 (예: 248 × 57) |

- 곱하는 수가 두 자리일 때 끝자리가 0인 수(예: 30, 50)는 내지 않습니다. 곱해지는 수의 끝자리도 0이 아닙니다.
- **제한 시간이 없습니다.** 모든 문제를 천천히 풀 수 있고, 타이머 막대도 나오지 않습니다.
- **배우기:** 자릿수별 세로셈을 보여 줍니다. 곱하는 수가 한 자리이면 올림 표시를 윗자리에 붙이고, 두 자리이면 일의 자리 곱과 십의 자리 곱(한 칸 왼쪽으로 옮긴 줄)을 나눠 쓴 뒤 더합니다. 풀이 순서는 자리마다 "7 × 5 + 2(올림) = 37. 7을 쓰고 3을 올려요."처럼 한 줄씩 설명합니다.
- **연습하기·도전하기(세로셈 입력):** 문제를 세로셈으로 보여 주고 칸을 눌러 입력합니다. 연습하기와 도전하기는 입력 방식이 같습니다. 이전의 보기 4개 방식은 쓰지 않습니다.
  - 맨 아래 줄이 **답**입니다. 답 칸은 자릿수만큼(곱해지는 수와 곱하는 수의 자릿수를 합한 만큼) 나오고, 일의 자리부터 숫자를 누르면 왼쪽 칸으로 자동으로 넘어갑니다. 중간에 빈 칸이 있으면 채점하지 않고 알려 주며, 맨 앞 칸을 비우거나 0을 써도 같은 수로 봅니다.
  - 맨 위 작은 칸은 **올림 메모**입니다. 곱해지는 수의 십의 자리부터 위쪽에 적어 둘 수 있습니다.
  - 곱하는 수가 두 자리이면 답 위에 **자릿수별 곱셈 메모 두 줄**이 나옵니다. 첫 줄에 곱하는 수의 일의 자리를 곱한 값을, 둘째 줄에 십의 자리를 곱한 값을 한 칸 왼쪽으로 옮겨 적고(일의 자리에는 `0`이 미리 표시됩니다), 두 줄을 더한 값을 답 줄에 씁니다.
  - 올림 메모와 곱셈 메모는 풀이를 돕는 용도이며 채점에는 쓰이지 않습니다. 채점은 맨 아래 답 줄만 봅니다.
  - 키보드에서는 숫자 키, Backspace, Enter(확인), 방향키(←/→로 칸 이동, ↑/↓로 줄 이동)를 쓸 수 있습니다.
  - 틀리면 올림 표시가 붙은 세로셈 풀이와 자리별 설명을 보여 준 뒤 다시 출제합니다.
- **범위를 정해서 도전하기:** 1-5단계 중 원하는 단계를 여러 개 골라 그 범위에서만 출제합니다.
- 틀린 문제는 풀이를 보여 준 뒤 다시 출제됩니다.

### 파닉스 놀이터

한국 초등학생이 영어 파닉스를 **소리 중심**으로 배웁니다. 글자 이름이 아니라 글자가 내는 소리를 연결하는 것이 원칙입니다. 지금은 1단계(`s a t p i n`)와 2단계(`m d g o c k`)가 있습니다. 단계 목록에서 단계를 고르면 게임 4개가 나옵니다.

| 게임 | 설명 |
| --- | --- |
| 소리 듣고 고르기 | 들려주는 소리에 맞는 글자를 3개 중에서 고릅니다. `c`, `k`처럼 같은 소리를 내는 글자는 한 보기에 함께 나오지 않습니다. |
| 단어 만들기 | 단어를 듣고 글자 타일을 눌러 만듭니다. 타일을 누르면 글자 이름이 아니라 그 글자의 소리가 납니다. 타일은 단어에 쓰이는 글자 + 섞는 글자 3개입니다. |
| 소리 합치기 | 소리를 하나씩 이어서 듣고 단어 카드 3장 중에서 고릅니다. 오답 보기는 철자가 비슷한 단어입니다. |
| 사이트 워드 | 규칙대로 읽히지 않는 단어(I, a, the, to …)를 듣고 글자 카드에서 고릅니다. 누적 사이트 워드가 3개 이상일 때 열리며 6문제입니다. |

- 단계마다 추천 게임이 있고, 추천 게임을 모두 한 번 이상 마치면 다음 단계가 열립니다. 단계 목록의 "모든 단계 열기"로 건너뛸 수도 있습니다.
- 한 판은 10문제(사이트 워드 6문제)이고, 새 항목 약 70% + 이전 단계 복습 약 30%로 구성됩니다. 틀린 문제는 3문제 뒤에 다시 나오고, 같은 항목을 연속 3번 맞히면 숙달로 보아 덜 나옵니다.
- 별은 판마다 처음 시도에서 맞힌 비율로 1~3개(최소 1개)이며 최고 기록이 저장됩니다. 오답일 때는 정답 소리를 다시 들려주고 넘어갑니다. 감점이나 큰 실패 연출은 없습니다.
- **제한 시간이 없습니다.** 천만냥냥은 말풍선으로만 응원합니다. 진행(소리·단어별 연속 정답과 틀린 횟수, 단계별 별)이 프로필별로 저장되고, 답 하나하나는 대시보드의 푼 문제 수를 위해 `ph_attempts`에 기록됩니다.
- **소리:** 헤더의 소리 버튼은 효과음에만 적용됩니다. 파닉스 소리는 학습 내용이라 항상 재생합니다. 음원은 `phonics/audio/`의 mp3이고, 파일이 없는 항목만 브라우저 음성(`speechSynthesis`)으로 임시 대체하며 이때 화면 아래에 안내가 나옵니다. 브라우저 음성은 단독 음소를 정확히 발음하지 못하므로 학습용으로는 쓰지 않습니다.

음원과 콘텐츠:

```
phonics/
├─ data/      stages.json (단계 목록) · stage1.json · stage2.json
├─ audio/
│   ├─ phonemes/  소리 (직접 만든 음원)
│   ├─ words/     단어 (로컬 Qwen3-TTS, 화자 Aiden으로 합성)
│   └─ sight/     사이트 워드 (합성 스크립트가 만든다. 파일이 없으면 브라우저 음성으로 대체)
└─ synth_phonics.py   단어·사이트 워드 음원 합성·점검 스크립트
```

- **새 단계 추가:** `phonics/data/stageN.json`을 만들고 `phonics/data/stages.json`에 파일명을 추가한 뒤 `phonics/audio/` 파일을 채웁니다. 코드 수정은 필요 없습니다. 데이터가 어긋나면(철자와 `tiles`가 다르거나, 아직 배우지 않은 글자를 쓰는 경우 등) 게임 대신 오류 목록이 나옵니다.
- **정답 판정:** 한 소리에 글자가 여럿(`c`/`k`)일 수 있어서 글자가 아니라 **소리** 기준으로 판정합니다.
- **음원 합성 스크립트:** `pip install -U qwen-tts soundfile numpy`와 PATH의 `ffmpeg`가 필요합니다. `cd phonics && python synth_phonics.py words --dry-run`으로 대상만 확인하고, `python synth_phonics.py words --stage 2`로 그 단계의 단어와 사이트 워드를 합성하며(이미 있는 파일은 건너뜀), `python synth_phonics.py check --stage 2`로 JSON에 적힌 음원이 모두 있는지 점검합니다. 사이트 워드는 철자대로 읽히지 않는 단어가 있어서 글자 대신 JSON의 `hint`(`uh`, `thuh` 등)를 읽히고, 마음에 들지 않으면 스크립트의 `WORD_TEXT_OVERRIDE`로 입력 문구를 바꿔 `--only 단어`로 다시 합성합니다. 음소는 합성하지 않고 직접 만듭니다.
- 음원은 이 저장소(공개)에 그대로 들어 있어 정적 호스팅에서 누구나 받을 수 있습니다. 천만냥냥 음성처럼 승인된 계정만 받게 하려면 비공개 버킷으로 옮기고 `phonics.js`의 `sayItem()`에서 서명 URL로 재생하도록 바꿔야 합니다.

## 로그인과 데이터 저장

### 동작 방식

1. 처음 열면 로그인 화면이 나오고, **Google 계정**으로만 로그인할 수 있습니다. 로그인하지 않으면 게임 화면에 들어갈 수 없습니다.
2. 처음 로그인한 계정은 **승인 대기** 상태가 되어 "가입 신청이 접수됐어요" 화면만 보입니다. 관리자가 승인해야 쓸 수 있습니다(아래 "가입 승인").
3. 승인된 계정(보통 부모님) 아래에 **아이 프로필**을 최대 6개 만듭니다. 프로필마다 진행 상황이 따로 저장됩니다. 게임 화면 위쪽 이름 버튼으로 프로필을 바꾸거나 새로 만들고, 삭제할 수 있습니다(삭제하면 그 프로필의 진행 상황과 풀이 기록도 함께 지워집니다).
4. 이 기기에 예전 방식(로그인 없이)으로 저장된 진행 상황이 있으면, 첫 프로필을 만들 때 가져올지 고를 수 있습니다.
5. 같은 계정으로 로그인하면 다른 기기와 브라우저에서도 이어서 할 수 있습니다. 마지막에 쓴 프로필은 기기마다 기억해 바로 열어 줍니다.

### 저장하는 데이터

| 테이블 | 내용 |
| --- | --- |
| `members` | 계정별 승인 상태(`pending` 승인 대기 / `approved` 승인 / `blocked` 차단)와 이메일. 새 계정이 생기면 자동으로 `pending` 행이 만들어집니다. |
| `profiles` | 프로필 이름. 계정(`owner_id`)에 딸려 있습니다. |
| `profile_state` | 프로필별 학습 진행(구구단 숙련도, 별, 선택한 탭과 범위, 덧셈·뺄셈·곱셈 단계별 기록, 파닉스 소리·단어별 기록과 별)과 설정(소리). |
| `attempts` | 문제를 풀 때마다 한 줄: 모드(연습/도전), 놀이터, 연산, 단계, 두 수, 정답 여부, 처음 나온 문제인지, 시간 초과 여부, 낸 답, 걸린 시간(ms). |
| `ph_attempts` | 파닉스에서 답할 때마다 한 줄: 단계, 게임(A-D), 소리 id 또는 단어, 정답 여부, 처음 나온 문제인지. |

대시보드는 두 테이블을 `dashboard_activity()` 함수로 하루 단위로 집계해 읽습니다(로그인한 계정의 RLS가 그대로 적용됩니다).

- 진행 상황은 바꿀 때마다 기기에 먼저 적고, 약 1초 뒤 서버로 올립니다. 올리지 못하면 8초마다 다시 시도하고 "저장하지 못했어요" 표시가 나옵니다. 기기에 적어 둔 값과 서버 값이 다르면 더 최근 것을 씁니다.
- 풀이 기록은 모아 두었다가 10개가 되거나 홈 화면으로 돌아갈 때, 탭을 닫거나 숨길 때, 프로필을 바꾸거나 로그아웃할 때 올립니다. 올리기 실패한 기록은 기기에 남겨 두었다가 다음에 다시 올립니다.
- 프로필 이름은 별명으로 써도 됩니다. 아이의 실명을 꼭 넣을 필요는 없습니다.

### 설정 순서

1. [Supabase](https://supabase.com)에서 프로젝트를 만듭니다.
2. 대시보드 **SQL Editor**에 `supabase/schema.sql` 전체를 붙여 넣고 실행합니다. 다시 실행해도 안전합니다. 이미 운영 중이라면 **활동 기록 대시보드를 배포하기 전에** 한 번 더 실행하세요(`ph_attempts` 테이블과 `dashboard_activity()` 함수가 추가됩니다). 실행 전에 새 코드가 먼저 배포되면 파닉스 기록만 서버에 올라가지 못하고 기기에 쌓이며, 다른 놀이터 기록은 영향이 없습니다.
3. **Google 로그인 켜기**
   - Google Cloud Console에서 OAuth 클라이언트 ID(웹 애플리케이션)를 만듭니다.
   - 승인된 리디렉션 URI에 `https://<프로젝트 ID>.supabase.co/auth/v1/callback`을 넣습니다.
   - Supabase 대시보드 **Authentication > Sign In / Providers > Google**에서 켜고 클라이언트 ID와 보안 비밀을 넣습니다.
4. **Authentication > URL Configuration**에서 Site URL을 배포 주소(예: `https://<계정>.github.io/huh_yunji/`)로 하고, Redirect URLs에 배포 주소와 로컬 개발 주소(예: `http://localhost:8000/`)를 추가합니다. 여기 없는 주소에서는 로그인이 거부됩니다.
5. 프로젝트 화면의 **Connect** 버튼에서 Project URL과 **publishable 키**(`sb_publishable_...`)를 확인해 `index.html` 위쪽의 설정에 넣습니다. 예전 방식의 `anon` 키(Settings > API Keys의 Legacy 탭)도 같은 칸(`supabasePublishableKey`)에 넣으면 동작합니다.

```html
<script>window.GUGUDAN_CONFIG = { supabaseUrl: 'https://xxxx.supabase.co', supabasePublishableKey: '...' };</script>
```

### 가입 승인

가입(첫 Google 로그인)은 누구나 할 수 있지만, 승인되기 전에는 프로필과 데이터를 읽거나 쓸 수 없습니다. 화면에서만 막는 것이 아니라 DB의 RLS가 막기 때문에, 앱을 우회해도 접근되지 않습니다. 승인과 차단은 Supabase 대시보드 **SQL Editor**에서 합니다. 앱 안에서는 바꿀 수 없습니다.

```sql
-- 승인 대기 중인 계정 보기
select email, created_at from public.members where status = 'pending' order by created_at;

-- 승인
update public.members set status = 'approved', decided_at = now() where email = 'parent@gmail.com';

-- 차단(이미 승인한 계정도 바로 접근이 막힙니다)
update public.members set status = 'blocked', decided_at = now() where email = 'parent@gmail.com';
```

- **관리자 본인도 처음에는 승인 대기입니다.** 스키마를 실행한 뒤 내 계정으로 한 번 로그인하고, 위 승인 SQL로 내 이메일을 승인하세요.
- `schema.sql`을 처음 실행할 때 이미 가입해 있던 계정은 자동으로 승인됩니다.
- 대기 중인 사용자는 화면의 "승인 확인" 버튼으로 다시 확인할 수 있습니다. 승인 직후에는 이미 열려 있는 화면을 새로고침하지 않아도 됩니다.
- 사용 중에 차단하면 다음 저장부터 실패하고 "저장하지 못했어요"가 나옵니다. 다시 로그인하면 차단 안내 화면이 나옵니다.

### 보안과 한계

- publishable 키(또는 legacy `anon` 키)는 브라우저에 그대로 보이는 **공개 값**이라 코드에 넣어도 됩니다. `sb_secret_...`와 `service_role` 키는 RLS를 우회하는 관리자 키이므로 절대 넣지 마세요.
- 데이터는 Supabase의 **행 단위 접근 제어(RLS)**로 지킵니다. 로그인하지 않은 요청은 어떤 테이블도 읽거나 쓸 수 없고, 승인되지 않은 계정도 마찬가지입니다. 승인된 계정은 자기 프로필과 그 프로필에 딸린 데이터만 읽고 쓸 수 있습니다. 풀이 기록은 추가와 조회만 되고 고치거나 지울 수 없으며(프로필을 지울 때 함께 지워짐), 프로필은 계정당 6개까지입니다. `supabase/schema.sql`에 정책이 모두 들어 있습니다.
- 정적 호스팅이라 로그인 화면은 **보기 위한 문 역할**입니다. `index.html`과 JavaScript 코드는 누구나 내려받아 볼 수 있습니다. 로그인하지 않은 사람이 볼 수 없는 것은 **저장된 사용자 데이터**입니다. 게임 코드 자체를 숨겨야 한다면 서버에서 인증을 확인하고 파일을 내려 주는 호스팅이 필요합니다.
- 로그인 정보(세션)는 브라우저에 저장되어 새로고침해도 유지됩니다. 로그아웃하면 이 기기에 남긴 미전송 기록은 그대로 두고, 화면의 데이터만 비웁니다.

### 천만냥냥 음성

음성 파일에 저작권이 있어서 이 저장소와 정적 호스팅에는 올리지 않고, Supabase Storage의 **비공개 버킷**(`protected-assets`)에 둡니다.

- **읽기 제한:** `supabase/schema.sql` 마지막의 정책이 승인된 계정(`public.is_approved()`)에게만 읽기를 허용합니다. 로그인하지 않았거나 승인되지 않은 계정, 공개 주소로는 받을 수 없습니다. 쓰기 정책이 없어서 업로드와 삭제는 관리자(대시보드)만 할 수 있습니다.
- **파일 위치:** 대시보드 Storage의 `protected-assets` 버킷 `voice/v1/nyang/` 아래에 `ok_01.mp3`, `bad_01.mp3`, `slow_01.mp3`, `hi_02.mp3`, `result_01.mp3` 같은 이름으로 올립니다.
- **시작 화면:** 브라우저는 사용자가 페이지를 한 번도 누르지 않은 상태에서는 소리를 막습니다. 새로고침하거나 로그인하고 돌아와 마지막에 쓴 프로필로 바로 들어가는 경우가 여기에 해당합니다. 이때는 홈 대신 "시작하기" 화면을 먼저 보여 주고, 화면을 누르면 홈으로 가면서 인사 음성이 나옵니다. 프로필을 직접 눌러 들어오거나, 소리를 꺼 둔 프로필, 이미 화면을 눌렀던 경우에는 시작 화면 없이 바로 홈으로 갑니다.
- **구성:** `manifest.json`이 대사 문구와 파일 경로를 짝지은 목록이고, `voice.js`가 로그인한 사용자의 권한으로 mp3를 내려받아 재생합니다. 로그인 후 미리 받아 두고, 로그아웃하면 기기에 저장된 파일도 지웁니다.
- **대사를 바꿀 때:** `index.html`의 `NY` 대사 표를 고친 뒤 음성을 다시 만들어 올리고 `manifest.json`을 갱신합니다. 만드는 방법은 `tools/voice/README.md`에 있습니다. 같은 경로의 파일을 덮어쓰면 이미 받아 둔 기기가 옛 음성을 계속 쓰므로, 음성을 다시 만들 때는 `voice/v2/`처럼 경로 접두어를 바꿔 올리고 `manifest.json`의 경로도 바꿉니다.
- **배포 전 확인:** 로그아웃 상태와 승인되지 않은 계정에서 파일이 내려받아지지 않는지 확인합니다.

## 진행 데이터

진행 상황은 프로필 단위로 Supabase `profile_state`에 저장됩니다(위 "로그인과 데이터 저장" 참고).

- 저장 항목: 구구단 숙련도, 별 개수, 소리 설정, 선택한 탭과 범위, 덧셈·뺄셈과 곱셈의 단계별 최고 별 점수, 푼 문제 수, 파닉스의 소리·단어별 연속 정답과 틀린 횟수 및 단계·게임별 최고 별(`progress.ph`).
- 같은 계정이면 어느 기기에서든 이어집니다. 새로고침이나 시크릿 모드와 상관없이 로그인하면 복원됩니다.
- 브라우저 `localStorage`에는 서버로 올리기 전의 임시 사본(`gugudan-nori-v2:pending:<프로필>`), 아직 못 올린 풀이 기록, 마지막에 쓴 프로필만 둡니다. 로그인 도입 전에 쓰던 `gugudan-nori-v1` 키는 첫 프로필을 만들 때 가져오기용으로만 읽습니다.

## 구조

`index.html` 하나에 구구단·덧셈·뺄셈·곱셈의 마크업, CSS, JavaScript와 캐릭터 이미지가 들어 있습니다. 파닉스 놀이터는 `phonics.js`(게임·출제)와 `phonics.css`로 따로 두었고, 앱이 `createPhonics()`로 불러 쓰면서 저장·화면 전환·소리 버튼·풀이 기록을 빌려줍니다. 활동 기록 대시보드도 `dashboard.js`(조회·화면)와 `dashboard.css`로 따로 두었고, 앱이 `createDashboard()`로 불러 쓰면서 로그인한 계정의 프로필 목록과 화면 이동을 빌려줍니다. 탭 아이콘은 `favicon.ico`, 천만냥냥 음성 재생은 `voice.js`와 `manifest.json`으로 따로 두고, 데이터베이스 스키마는 `supabase/schema.sql`에 있습니다. 음성 파일을 만드는 도구(대본 생성, 합성, 후처리 스크립트)는 `tools/voice/`에 있고, 사용법은 그 폴더의 `README.md`를 보세요. 게임 코드는 순수 JavaScript이고, 외부 라이브러리는 로그인과 저장을 위한 `@supabase/supabase-js` 하나만 CDN(jsDelivr, 버전 고정 + SRI 해시)에서 불러옵니다.

- **문제 표현:** 모든 문제를 `{a, b, op, lv}` 형태로 다룹니다. `op`는 구구단 `*`, 덧셈 `+`, 뺄셈 `-`, 곱셈 놀이터 `x`입니다. 퀴즈 진행, 타이머, 피드백, 결과 화면은 세 놀이터가 같은 엔진을 씁니다.
- **타이머:** `requestAnimationFrame`으로 마감 시각까지 남은 시간을 계산하고, 탭이 가려지면(`visibilitychange`) 멈춥니다. 제한 시간은 문제의 연산과 단계로 정해지며, 곱셈 놀이터는 0(제한 없음)이라 타이머를 시작하지 않습니다.
- **문제 생성:** 덧셈·뺄셈 문제는 단계별 생성기가 만들며 결과 범위 조건을 항상 만족합니다. 풀이 설명도 같은 숫자로 생성하므로 설명과 정답이 어긋나지 않습니다.
- **디자인:** 모눈종이 배경, 단마다 다른 색상, 밝은/어두운 테마를 지원합니다. 좁은 화면(약 400px)에서도 가로 스크롤이 생기지 않도록 맞췄습니다.

## 브라우저 지원

`requestAnimationFrame`, `localStorage`, `fetch`, CSS 변수를 지원하는 최신 데스크톱·모바일 브라우저(Chrome, Edge, Safari, Firefox)에서 동작합니다.
